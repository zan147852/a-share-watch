# 连板接力顺序筛选 v0.2

程序v0.8扩展原有连板模块，支持首板→二板、二板→三板及三板以上→更高板。全部阈值是试验参数，尚未证明盈利。

## 当前手机操作流程

1. 原网页打开「连板接力」，选择已完成收盘报告的日期，不把旧数据当盘中数据。
2. 切换二板、三板或更高板，按卡片六关查看实际值、排除和缺项。优先看「新规则盘后通过」，没有合格候选就等待。
3. 下一实际交易日在行情软件核实实时依据，展开「填写盘中回封记录与私人计划」。
4. 填本金、当日实际涨停价、失效位、两只题材同伴的现价/昨收、业务催化原文、触板/板下成交/回封时间和退出条件，再点击「核对记录与股数」。
5. 盘后条件完整、人工记录齐全且能买至少100股，才允许导出私人计划；这只是文件，没有委托或成交。
6. 用户自行下单，排队时再次开板撤销未成交委托。实际成交另记，次日按事前退出条件复核。

草稿只在当前站点的本机浏览器localStorage保存，按规则版本、日期、代码分开，刷新恢复。浏览器清除数据会丢失草稿，可使用清除按钮。不上传本金、个人计划或草稿。

## 当前六关参数

| 顺序 | 固定口径 | 获取方式 |
|---|---|---|
| 1 板数 | 连续交易日收盘涨停，目标=昨日板数+1；初期普通沪深主板 | 日线核验 |
| 2 市场 | 覆盖≥98%；涨跌停/前日反馈完整；晋级数据完整；昨日涨停平均收盘反馈≥0；涨停≥15；跌停<15 | 收盘核验 |
| 3 题材 | 完整产业题材同日收盘涨停≥3；业务和催化原文有效；盘中另2只同伴高于昨收 | 收盘代理+人工 |
| 4 个股 | 成交额≥1亿元；首封≤10:30；开板≤3次；非一字 | 日期、价格、板数一致的封板源 |
| 5 回封 | 核心连板未明显走弱；触板→板下成交→回到实际涨停价并有新封单 | 人工实时记录 |
| 6 计划 | 每只上限3000元，每天最多新买1只；风险预算0.5%，费用预留20元；股数取金额与风险约束较小者，按100股取整；三种退出条件齐全 | 计算+人工 |

高板额外排除：目标≥4板，前3个完整交易日成交量V0>V1>V2，报告日量>V2且发生开板，即「连续两次缩量后首次放量开板」。是排除代理，未触发不代表安全；缺量或封板记录保持未知。

数量不完整时仅为已核验下限，不据此放行；但已核验跌停下限≥15可以直接暂停。晋级率只要求数据完整，无新增比例门槛。评分不能覆盖缺项。状态为通过、排除、缺证据、待人工；新候选B为盘后通过待人工、C缺项、D排除，不产生自动买入级别A。

## 冻结、兼容与私人账本

顺序参数在 `config.json → chain → sequential`。共享规则 `public/relay-rules.js`用于后端、网页与账本。收盘策略 `v0.2-chain-observation`，人工卡 `v0.2-relay-sequential`。旧版完整事前报告跨版本不覆盖；网页对旧报告的新规则复核不计新规则事前成绩。

旧v0.1只含二/三板，网页从同日原快照补充已核验高板，标「旧快照补充，非原事前候选」，不回写、不纳入旧成绩；缺题材/量能保持未知。新扫描含全部已核验正整数板数。累计观察按原规则版本、路线、级别分组，观察涨跌不是交易收益。

导出文件含单笔计划及人工依据，先与本机现有完整账本合并再导入。`node chain-ledger.js import 完整账本.json`替换整份账本并留备份，不能用单笔文件覆盖历史。账本仍在被Git忽略的 `.private`。

新计划再次核验人工依据、回封时间、涨停价、金额限制和退出条件一致；未来/历史记录不能导出为当前事前计划。成交校验每日新买数量、最高买价、计划股数、100股、T+1及费用。实际损失可能远超计划；20%压力估算不是最大损失。

程序无实时竞价/逐笔监听、自动推送、下单或止损；人工完整记录仍须临下单核对实时条件。每天15:25云端任务只做收盘准备，免费数据/调度可能延迟。测试覆盖门槛边界、未知、高板、时间顺序、仓位、版本及账本；浏览器验收手机布局、草稿恢复和导出兼容。
