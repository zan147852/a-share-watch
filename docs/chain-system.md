# 二板、三板接力观察模块 v0.1

这版先完成自动筛选和事前留档：每日云端收盘扫描 → 全市场快照 → 连板核验 → 情绪标签 → 次日观察候选 → 名单冻结 → 次日自动反馈。手机打开原网页即可查看，不需要本地手动筛选。竞价、盘中买点、推送和券商执行尚未接入。

## 页面如何使用

打开“二板与三板观察”，选日期和候选范围。

- 今天首板进入“首板 → 二板观察”；今天二板进入“二板 → 三板观察”。已完成三板不属于初版买三板候选。
- A：允许次日观察；B：等待分歧确认；C：只记录，证据不足或低分；D：明确排除。
- 评分不是胜率；收盘候选不是盘中买入信号。今日最低价和次日涨停参考价也不是自动委托价。
- 数据异常、未知、缺覆盖都显示出来，不能把0个已核验候选解释成全市场没有机会。
- 次日自动显示前一交易日完整冻结名单的开盘溢价和收盘变化；它们是观察反馈，不是收益。

## 数据和规则

范围沿用现有系统：主板与创业板（含301），排除ST、退市名称和上市不足60交易日。沪深主板常规10%、创业板20%，按分四舍五入计算涨跌停。先使用复权日线宽松预筛，再抓未复权日线核验；以指数日线为交易日序列。

除权前后涨幅不一致、特殊交易状态、重复日线、停牌缺口或历史窗口边缘都保持未知。只核验收盘封板；触及涨停但未封住作为日线炸板代理。炸板率定义为“触板未封住数量 / 当日触板数量”，与收盘涨停池中的盘中开板次数不同，不从30分钟K线推断秒级封板。

涨停池先核对返回日期，再核对价格和板数；一致后才使用首次封板、开板次数、目标日成交额和换手率。接口失败不补0。其他成交额、市值标记其采集日期，历史重扫不能用今日数据替代。

市场状态优先判断退潮，再冰点、上升、修复，其余完整环境列为高位分歧；覆盖不足或昨日反馈未知则证据不足。阈值集中在 `config.json` 的 `chain` 中，全部是待检验参数。情绪采用范围内股票的涨跌停、炸板率、昨日涨停收盘反馈与晋级率；高度只显示事实，不独立判定允许交易。

评分总计100：市场20、题材25、早封15、封板稳定15、量能15、成交容量10。缺项计0，同时标C；不按已知项重新归一化。题材沿用五步主线模块的已采集成分，覆盖不到的题材不宣称没有联动。硬排除：当日一字、成交额不足、已覆盖题材联动不足、退潮/冰点。初版阈值较保守，可能错过机会。

## 保存与冻结

- `public/data/market-snapshot-日期.json`：全市场有效特征、缺失名单、未复权核验事实、封板源和异常。复权字段明确标记，不用于委托。
- `public/data/chain-日期.json`：情绪、候选、分数构成、排除/缺失、参考计划、次日复盘。
- `public/data/chain-manifest.json`：日期目录。
- `public/data/chain-review.json`：累计事前观察反馈，以及最近5个有效观察日按接力路线/级别汇总。

完整且当日生成的报告不因重跑更换名单；部分报告可补全，记录新的冻结时刻。补全跨日则标历史重扫，不能计事前成绩。复盘必须使用实际上一交易日、完整事前报告且冻结早于次日09:30；缺任何成员数据时不缩小分母、平均反馈留空。

每日快照是观察数据备份，既有行情缓存仍由GitHub Actions保存。公开仓库会公开候选和市场数据；账户、成交和持仓不能放入 `public/data`。

## 买入、风控和成交复盘

收盘阶段只列“二板弱转强”“二板分歧回封”“三板核心接力”的待验证模式。没有竞价和盘中数据时不补造触发时间。下一阶段要先采集真实分钟/逐笔快照，再固定量化信号与退出规则。

买入前的私人计划需填写：模式、计划创建时间、目标交易日、最高买价、结构失效价、失效条件、次日退出条件、时间退出条件。参考低点不自动变成止损。股数取风险预算与金额上限较小值并向下取整100股；默认单笔账户风险0.5%、金额上限10%为试验参数。T+1和跌停使实际亏损可能超出计划风险。

`lib/chain-risk.js` 计算计划股数；`lib/chain-ledger.js` 核验计划和真实成交。成交费用填写券商实际费用合计，包括佣金、规费和税费，避免重复扣费。

账本只保存在被Git忽略的 `.private`。暂不从手机网页写入公开服务器。可以从券商导出整理成下列结构；这是格式示例，金额与股票是虚构的，不能作为真实成绩。

```json
{
  "plans": [{
    "id": "example-01", "code": "600001", "mode": "二板弱转强",
    "createdAt": "2026-10-09T09:40:00+08:00", "tradeDate": "2026-10-09",
    "equity": 50000, "entry": 10, "stop": 9.5,
    "riskFraction": 0.005, "maxPositionFraction": 0.1, "costReserve": 20,
    "exitRules": {"invalidation": "跌破事前结构位", "nextDay": "预期失败时退出", "timeExit": "下一交易日14:30复核"}
  }],
  "fills": [],
  "misses": [{"planId": "example-01", "reason": "排队未成交"}]
}
```

成交格式：`id / planId / side(buy或sell) / date / at(含时区) / shares / price / fees`。程序拒绝买入超过计划股数或买价上限、买入非100股单位、成交早于计划、同日买入卖出、卖出超出可卖股数和重复编号。每个计划暂为一轮首次建仓，不支持自动加仓。

```powershell
node chain-ledger.js import C:\你的私人目录\完整账本.json
node chain-ledger.js review
```

导入的是整份账本，已有账本会留备份。报告在 `.private/chain-review.json`，只统计完整平仓轮次；持仓和未成交都不作已实现收益。当前不支持券商CSV自动映射、锁屏提醒、自动下单或自动止损。账户整体回撤和同题材总风险控制仍须在后续账户模块接入，不能把单笔仓位工具当成完整账户风控。

## 验收和后续

运行 `node --test test/*.test.js`。新增测试覆盖10%/20%、真实交易日连续性、除权/停牌/未来数据、未知数据、候选目标板数、冻结/缺分母、账户股数、T+1和真实费用。

这版先连续保存至少20个交易日，检查事实覆盖和冻结记录，再对三种模式分别采集盘中信号。免费GitHub定时任务负责收盘研究；分钟级盘中监听需要另一个持续运行环境，不能把GitHub定时任务当成实时打板服务。推送的触发、到达、失效时刻也需留档。

每周先看覆盖与执行偏差，再看分模式、分市场状态的观察反馈；实际成交收益需用私人账本。参数版本固定，修改后单独统计，不把历史回看赢家当成有效性证明。
